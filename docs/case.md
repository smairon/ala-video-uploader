## Постановка задачи
Ты хороший python разработчик. Тебе поставили задачу

Есть некоторый сервис, который записывает rtsp поток с камеры в виде чанков в формате .ts на диск. Каждый rtsp поток имеет имя и записывается в папку с этим именем. Так же в папку записывается плейлист playlist.m3u8 который содержит список чанков для последующего воспроизведения.

## Вводные
- Длительность чанков - 10 секунд
- Длительность записи видео - до 10 часов
- Битрейт видео - 512кбит/сек
- Кодек - h.264
- Запись может обрыватся и возобновляться в любой момент в течении 10 часов с момента старта
- Плейлист должен быть доступен к просмотру череp HLS.js плеер в браузере с момента загрузки первых чанков в s3

## Постановка задачи
Тебе нужно спроектировать и реализовать сервис, который в режиме демона осуществляет загрузку этих чанков и плейлистов в бакет s3. После успешной загрузки в s3 чанки должны удаляться (не обязательно сразу). Плейлист не должен удаляться 24 часа с момента создания.

- Сервис должен работать как docker контейнер, к которому монтируется volume с данными (чанками и плейлистами)

- Нужно написать сам сервис (в папке src), Dockerfile, docker-compose.yml с тестовым инстансом seaweedfs

- Так же, для тестирования, надо добавить функционал эмуляции записи видео потока в чанки и m3u8 плейлист через ffmpeg. Семпл видеофайла, который можно нарезать на чанки лежит в data/sample.mp4

- В тестовых целях сервис должен иметь возможность запускаться локально из терминала.

## Инфраструктурные вводные
- В качестве s3 используется seaweedfs
- Сервис должен быть написан на python 3.14. C соблюдением SOLID принципов, особенно принципов единой отвественности и инъекции зависисмостей. Все должно быть разложено по отдельным классам с минимальной связностью, которые принимают зависимости через контракты (Protocol). 
- В качестве менеджера окружений используется uv
- Виртуальное окружение хранится в .venv папке


>> Плейлист должен описывать всю 10-часовую запись как VOD или это скользящий live-плейлист с ограниченным окном?
Плейлист описывает всю запись с начала. Но надо как-то иметь возможность проставлять в плейлист признак того что запись гарантированно окончена спустя 10 часов после появления первого сегмента. До этого запись может быть продолжена в любой момент. 

>> Должна ли S3-копия храниться бессрочно, или срок в 24 часа относится также к объекту playlist.m3u8 в бакете?
В s3 все данные хранятся бессрочно. Удаление касается только локальных данных в volume. 24 часа нужно для того чтобы стрим 100% завершился с запасом.

>> Кто создаёт уникальную сессию записи: внешний рекордер можно изменить, или uploader должен вывести её сам?
Внешний recorder создает запись со следующей структурой

```
- data
  - recordings
    - {stream_id}
      2026-01-01T01:00:00.12345.ts
      2026-01-01T01:00:10.23455.ts 
      2026-01-01T01:00:20.23455.ts 
      ...
      playlist.m3u8
```  
То есть названия чанков монотонно возрастают и если после чанка N уже появился следующий чанк N+1, то запись в N гарантированно закончена и его можно смело загружать в s3. А вот последний чанк может еще дописываться, поэтому его загрузку нужно отследивать тщательнее.

Поэтому не нужны никакие сессии, поток всегда пишет чанки в свою папку.
